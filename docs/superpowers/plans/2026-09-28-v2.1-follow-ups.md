## Global constraints

- **Branch.** Work on `development`, and never push.
- **Commits.** Commit only with the user's permission.
- **Deployment values.** Nothing deployment-specific is hardcoded. New settings are env vars with safe defaults and a line in `.env.example`. Docs use example.com.
- **Keys.** API keys never appear in logs, events or responses.
- **User content.** No user content is logged at WARNING or above.
- **Refusals.** A document read route returns 404 to anyone who can't read the document, never 403 (the `can_read` SQL predicate, `server/auth/authz.py`).
- **Tests.** Every task leaves both suites green. The commands are:
  - `.venv/bin/python -m pytest server/tests -q`
  - `npx vitest run`
  - `npx eslint src`, which must be clean after Task 8.
- **Docs.** Every user-visible change gets a CHANGELOG `[Unreleased]` line and a correction to any doc that described the old behaviour.

## Review focus

1. A web page that is huge, slow or not HTML must not hold a chat turn for more than one fetch deadline.
2. A small model that writes its tool call as text must end up running the tool, not showing JSON as the answer. A real answer that merely *starts* with `{` must still stream.
3. Opening a document from the Library must never serve bytes to someone who can't read it. That covers a stranger, and a holder whose entry is unverified.
4. On a shared browser, the next signed-in user must not see or open the previous user's local files.
5. A citation click on a reply about a document the user no longer has must fail with a notice, not a blank reader.

### Task 1: Cap web-search page fetches by size, time and type

**Why:** `fetch_and_extract` (`server/services/web_search.py:147`) calls `_safe_get`, which reads the whole body, and only then slices `resp.content[:MAX_RESPONSE_BYTES]`. In the C1 walk a 111 MB PDF held one turn for 6.5 minutes, and a hostile page can make the server buffer a body of any size.

**Change:**
- Stream the final hop (`client.stream(...)`) and stop reading at `MAX_RESPONSE_BYTES`.
- Wrap each page fetch, redirects included, in a total deadline: `WEB_SEARCH_FETCH_TOTAL_S`, default `15` seconds. Add it to `.env.example`.
- Skip non-text content early. If `Content-Type` is present and is neither `text/*` nor `application/xhtml+xml`, return `None` without reading the body.
- Keep the existing SSRF re-check on every redirect hop unchanged.

**Tests** (httpx `MockTransport`):
- An endless body stops at the cap.
- A body that trickles past the deadline returns `None` within the deadline plus a small margin.
- `application/pdf` returns `None` without reading the body.
- A normal HTML page still extracts.

### Task 2: Recover tool calls that a model writes as text

**Why:** `llama3.2:3b` often emits `{"name": "search_document", "parameters": {"query": …}}` as reply text. It's saved as the answer. This happened in both walks and is the most visible failure a user of a small model sees.

**Change** (orchestrator step loop, `server/chat/orchestrator.py` around the `TextDelta` handling):
- While a step's text so far is only whitespace, or starts with `{`, or with a code fence followed by `{`, **hold** the text deltas instead of emitting them. Hold at most `TEXT_TOOLCALL_PROBE_CHARS = 2000` characters.
- As soon as the held text can't be a JSON object (its first non-space character isn't `{` or a fence), or the cap is passed, emit the held text as one `text-delta` and stream normally from then on.
- At the end of the step, if the held text parses (after stripping a code fence) as one object `{"name": <a tool offered on this step>, "parameters" | "arguments": {…}}`, and the provider returned no native tool calls, treat it as a native `ToolCallReady`:
  - run the tool;
  - emit the same tool events a native call would;
  - emit **no** text for it.
  - Log at DEBUG: `recovered text tool call name=<tool>`.
- Otherwise, emit the held text unchanged.

**Tests** (scripted provider):
- JSON-text tool call → the tool runs, the second step answers, and the stored content has no JSON.
- The same JSON in a code fence → recovered.
- JSON naming a tool that wasn't offered → emitted as text.
- A normal answer starting with `{` that isn't a tool-call shape → streamed unchanged.
- Plain prose → streamed with no hold at all (the first delta is emitted at once).

### Task 3: The Index button follows the document on first open

**Why:** In the A1 walk, a new Markdown file's Index button stayed on "Index" after the server had indexed it. The loaders call `setPdfFileName` before `saveBook` finishes writing to IndexedDB (`src/hooks/usePdfEngine.js` 248/303 for text and Markdown, 268/273 for PDF). The "document changed" effect in `App.jsx:666` then reads the bytes back from IndexedDB to hash them. If it loses that race, `currentDocId` stays null for the whole session, and progress written under the real hash is never shown.

**Change:**
- In all three loader paths, `await saveBook(...)` *before* the state update that sets the file name.
- Keep the recent-books refresh after it.
- If `saveBook` throws, still open the document, but show a toast: "Couldn't save this file locally — Index and chat about it may not work until you reopen it."

**Tests:**
- A `usePdfEngine` test: `saveBook` resolves after a delay, and `pdfFileName` must not be set before it resolves.
- An App-level test: on first open, the button reaches "Indexed" when the poller reports `indexed`.

### Task 4: The reader's local library belongs to the signed-in user

**Why:** The welcome screen's "Your Library" lives in the IndexedDB store `neural-pdf-library/books` (`src/db.js:6`), shared by everyone who uses the browser. In the A1 walk, user B saw and could open user A's files.

**Change:**
- Add `ownerId` to every saved record.
- `getRecentBooks` and `getBook` return only records whose `ownerId` matches the signed-in user's id (from `/v1/auth/me`).
- On sign-in, records with no `ownerId` (saved before this release) are claimed by the first user who signs in on that browser. That keeps a single-user install's library.
- On logout, nothing is deleted; the records just stop showing.
- With the dev loopback bypass (no auth), use `"local"` as the owner id.

**Tests:**
- Two users on one browser each see only their own records.
- A legacy record is claimed once.
- Logout hides the records.

### Task 5: Open a Library document in the reader (shared and project documents included)

**Why:** A person who receives a document by share or project sees it listed but can't read or ask about it: no route serves stored bytes, and Library rows don't open anything. Today sharing only changes a list.

**Change (backend):**
- Add `GET /v1/docs/{doc_id}/file`:
  - It requires the `reader` capability and uses the same `can_read` SQL predicate as `GET /v1/docs/{id}`. Unreadable → 404.
  - It streams the stored bytes (`FileResponse`) with the stored MIME type and `Content-Disposition: inline; filename="<the caller's own entry name, or the name the sharer gave>"`.
  - Stored bytes missing → `409 bytes_missing`, reusing the existing refusal and message.

**Change (SPA):**
- Each Library row gets an **Open** button.
- It fetches the bytes, saves them to the local library under the Task 4 owner, and opens them in the reader, the same as picking the file.
- The existing Index/Chat flow then just works, because the hash equals the doc id.

**Tests:**
- Route: owner 200; share recipient 200; project member 200; stranger 404; unverified pre-A1 holder 404; missing bytes 409; the filename comes from the caller's entry.
- SPA: Open loads the reader with the right file name and type.

**Docs:**
- `LIBRARY.md` "Sharing" and "Projects": say what a recipient can now do.
- USER_GUIDE: the Open button.

### Task 6: Click a citation to open that page

**Why:** Replies cite "(page 3)" or "[2] (page 3)" as plain text. A1's journey 2 expected the citation to open that reader page, and no code for that exists.

**Change:**
- In the assistant message renderer (`src/components/ChatView.jsx`), for a reply whose saved `doc_context` names a document (prefetch notes or `search_document` results carry `docId`), turn `page N` and `(page N)` in the reply text into buttons.
- A button opens that document at page N:
  - switch to the reader;
  - if the document isn't open, open it through Task 5's route;
  - then go to page N.
- If opening fails (404 or 409), show a toast and stay in chat.
- Don't linkify replies with no document context.

**Tests:**
- The renderer links "(page 4)" only when a `docId` is present.
- A click calls `onOpenCitation(docId, 4)`.
- The App handler opens and navigates, and shows a toast on 404.

**Docs:** fix `LIBRARY.md` ("a chat citation always opens to the right page" is only true after this task).

### Task 10: Provider errors say what happened; OpenRouter is verified

**Why:** In a check against a real OpenRouter key (2026-09-29), OpenRouter's free models answered `429` with the body `{"error": {"message": "Provider returned error", "metadata": {"raw": "… is temporarily rate-limited upstream. Please retry shortly …"}}}`. The user saw "The model provider returned an error: Provider returned error", which doesn't say that retrying later, or picking another model, would help. The same check verified with paid Gemma 4 and Mistral Small 3.2:
- the OpenAI-compatible adapter against OpenRouter across three turns;
- pins;
- a native `web_search` tool round;
- an image with a follow-up;
- provider-reported usage.

**Change:**
- In the shared provider error mapping (`server/llm/providers/base.py` and the adapters), map the HTTP status to a plain message. The existing `safe_error_message` redaction still runs on any provider text included.
  - `429` → "This model is busy or rate-limited at the provider. Try again in a moment, or pick another model." Append the provider's `error.metadata.raw` (redacted, trimmed) when present.
  - `401` / `403` → "The provider rejected this server's credentials. An admin needs to check the API key."
  - `402` → "The provider account is out of credit."
- Keep the error code `provider_error`, and keep the "no output and no usage → not charged" rule.
- **Docs:** `README.md`, `docs/DEPLOYMENT.md` and `docs/USER_GUIDE.md`, where they describe providers, say OpenRouter was verified (the models above), and that vLLM and LiteLLM use the same protocol but weren't run.
- **Env naming:** the env example must make clear that the key goes in `INFERENCE_<NAME>_API_KEY`. A bare `OPENROUTER_API_KEY` is ignored; the user tripped on exactly this.

**Tests:**
- An adapter test per status (429 with `metadata.raw`, 401, 402) through `httpx.MockTransport`, asserting the message.
- A test that an `sk-…` inside `metadata.raw` is redacted.
