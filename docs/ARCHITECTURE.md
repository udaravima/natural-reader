## The mental model

Neural Reader is a PDF/e-book reader with TTS read-aloud and an RAG-capable chat side. At runtime there are up to **five moving parts**:

| Process / container | Port (dev) | Role |
|---|---|---|
| Vite dev server (SPA) | 5173 | React frontend + **reverse proxy** for `/v1` and `/api` |
| FastAPI backend (`run.py`) | 8000 | TTS synthesis, doc RAG, chat-session storage, auth, tools |
| Postgres + pgvector | 127.0.0.1:5433 | users, sessions, documents/chunks+embeddings, chat sessions |
| Ollama | 11434 | chat model + `nomic-embed-text` embeddings + the reader sub-agent's model |
| SearXNG / Keycloak | 127.0.0.1:18043 / 18080 | web-search backend / local OIDC provider (dev rig) |

The frontend is a **single-page app with no router** (`src/App.jsx` is ~1300 lines, one component, a `viewMode` state toggling reader vs chat). The backend is **API-only** — it serves no static files. In dev, Vite proxies; in production, nginx does (see `deploy/nginx`). Either way the browser only ever talks to one origin.

Everything else in this document is detail on those two codebases.

## The one rule: same-origin `/v1`

If you remember one design constraint, remember this one. Every `/v1` fetch the SPA makes goes out with `credentials: 'include'` (`src/utils/apiFetch.js`) so the OIDC session cookie rides along. The browser refuses `credentials: 'include'` responses when the server answers with the wildcard `Access-Control-Allow-Origin: *` — and the backend's default CORS used to be the wildcard, for the browser extension, which called `/v1/synthesize` from arbitrary page origins. Since extension 0.2.0 it calls from its service worker with a Bearer token, which its host permission exempts from CORS, so the default is now no cross-origin caller at all).

The consequences chain out from there:

- A blank `apiHost` in the SPA (`buildApiUrl` in `src/utils/url.js`) produces a **relative URL** — same-origin. This is the only supported configuration for cookie auth.
- `vite.config.js` proxies `/v1` → `http://localhost:8000` and `/api` → `http://localhost:11434` so dev on :5173 is same-origin with everything.
- `localhost:5173 → localhost:8000` is **cross-origin** (different port = different origin), so any persisted `apiHost: 'localhost'` was silently broken by the auth work. `App.jsx` migrates the stale localStorage value to blank on mount (`migratePersisted('apiHost', 'localhost', '')`).
- Pinning `FRONTEND_ORIGIN` on the backend switches CORS to an exact-origin list and enables `allow_credentials` — for deployments where the SPA is hosted on a different origin than the API.

If the SPA ever shows the "backend isn't responding" gate while `curl localhost:8000/v1/health` works fine, check the browser console for a CORS complaint before blaming the backend — the request may be succeeding at the network layer and being discarded by the browser.

## Frontend

### App.jsx — the hub

`src/App.jsx` owns all global state and wires the engines. The order of things matters:

1. **Migration first.** `migratePersisted(...)` runs at the very top of the component body, before the hooks read localStorage, because the old default `apiHost='localhost'` predates cookie auth and is always CORS-dead now.
2. **Persisted settings** (`usePersistedState`, localStorage key prefix `neural-pdf-`): `darkMode`, `volume`, `scale`, `playbackSpeed`, `selectedVoice`, `isLocalhost` (see [traps](#invariants--traps) — despite the name it means "use Kokoro TTS, not Web Speech"), `apiHost`/`apiPort`, `requestTimeout` (seconds), `unlimitedBatchTimeout`, `viewMode` (`'reader'|'chat'`), `selectedModel` (a `provider:model` id; a pre-C1 bare model name is read as `ollama:<name>`), `chatTtsMode`, `chatAutoTts`, per-model inference overrides (`inferenceByModel`), `distractionFree`, layout knobs. **Removed in C1** (no longer read or written): `inferenceSource`, `ollamaHost`, `ollamaPort` — chat has no client-side provider selection any more.
3. **Engines**: `useAuth`, `useTheme`, `useMobileDetect`, `usePdfEngine`, `useTtsEngine`, `useChatEngine`, `useKeyboardShortcuts`.
4. **Per-document state maps keyed by sha256** (`docIndexByDocId`, `docConvertByDocId`, `docViewByDocId`) — switching documents never collides.
5. **The auth gate** renders *after all hooks* (rules-of-hooks safe) and short-circuits every render: `auth.state !== 'active'` → `<AuthGate>` alone. Note the subtlety: the gate blocks what's **displayed**, but App's hooks and effects still run — that's why you can see CORS errors in the console while staring at a login screen.

Big effects in App: the health probe (`GET /v1/health` once on mount → decides Kokoro vs Web-Speech fallback), the document hash + status fetch (sha256 of file bytes → `GET /v1/docs/{id}` to restore pipeline state), the **index pipeline** and **docling pipeline** handlers (both: register → upload → kick off → poll every 2s), and workspace restore from IndexedDB.

### Hooks

| Hook | Controls | Backend endpoints |
|---|---|---|
| `useAuth` | Auth state machine: `loading→active/anonymous/pending/disabled/error`. Any 401 anywhere (via apiFetch's global handler) resets to `anonymous`. | `/v1/auth/me`, `login` (full-page redirect), `logout` |
| `usePdfEngine` | Document load/render/extract. Pure client + IndexedDB; no backend. Sentence segmentation, mdast-based markdown pipeline, 5-book-per-user LRU library (scoped to whoever `setLibraryOwner` names — see `db.js`), 7-day reading progress. Browser-only chats (`chat_sessions`), the last workspace folder (`workspaces`, one record per user) and reading positions are scoped to the same owner; a pre-release browser's are claimed by its first sign-in. | — |
| `useTtsEngine` | Reader + chat + preview audio channels. The narration plays in every view (page text comes from the document, not the canvas, so it turns pages with the reader unmounted); one voice at a time: chat read-aloud pauses it (`pausedForChat`). Sentence queue with 2-ahead prefetch, in-flight dedup, cache eviction, 3-failure circuit breaker. Downloads: page / message / whole-book (3-worker parallel pool, client-side WAV stitch via `wavConcat`). | `POST /v1/synthesize`, `POST /v1/batch_synthesize` |
| `useChatEngine` | Chat driver. Every turn runs server-side: `postTurn` (`src/lib/chatStream.js`) POSTs `/v1/chat/sessions/{id}/turns` and reads the SSE response; `applyEvent` (`src/lib/chatEvents.js`) is a pure reducer turning each event into message state (text, thinking, tool panel, `data-context`/`data-notice` toasts, status). Session persistence, pins, event log, 429 interception (budget-exhausted toast), budget state for the meter, model list from `GET /v1/inference/models` (`src/lib/chatTransport.js`). No client-side tool execution, think-level retry chain, or NDJSON parsing — that all moved to `server/chat/` and `server/llm/`. | `POST /v1/chat/sessions/{id}/turns` (SSE); `GET /v1/inference/models`; sessions via sessionStore |
| `usePersistedState` | `useState` + JSON in localStorage; `migratePersisted` helper; reading-progress save/load with expiry — per user (`neural-pdf-progress@<userId>/<file>`, nothing while no user is known). | — |
| Others | `useKeyboardShortcuts` (Space/Esc/arrows/F for distraction-free), `useMobileDetect`, `useTheme` (Tailwind class maps). | — |

One design detail worth knowing before touching chat code:

- **Chat TTS prefetch is bounded to +2**: Kokoro serializes synthesis server-side under a global lock; queuing everything at once would just pile up. `speakMessage` (manual per-bubble read) fires all sentences immediately — the server serializes anyway.

The feature-rejection retry (a model 4xx's on tools or a thinking level, so the server retries once without it) now lives server-side in the provider adapters (`server/llm/providers/base.py`'s `FeatureMemory`/`settle_dropped`), reported to the browser as a `data-notice` event rendered as a toast — there's no client-side fallback chain to get backwards any more.

Pure companions: `inference.js` (per-model overrides, sent as the turn's `settings`; **unset means omitted from the request** — sending `null` would clobber Modelfile tuning), `pins.js` (max 6 pins, 12k char budget, dedup). `chatHistory.js` (the old client-side history/pin-preamble builder) is gone — the server assembles history now (`server/chat/context.py`).

### Persistence layer (lib/)

- **`sessionStore.js`** — chat sessions live in **two places**: legacy IndexedDB (pre-multi-user) and Postgres. Reads merge both, newest-first, tagged `source:'pg'|'local'`. Writes always target Postgres; the first message you send on a legacy-sourced session **copies it** onto Postgres via `POST /v1/chat/sessions/import` (create-only) so the original IndexedDB copy stays untouched. Chat needs the backend and Postgres both — there's no direct-to-Ollama fallback if either is down; a turn fails with a normal error toast instead.
- **`workspace.js` / `WorkspaceContext.jsx`** — folder-as-workspace support with two interchangeable backends (File System Access handle vs `webkitdirectory` snapshot) and a reducer-driven back/forward history for navigating markdown between files.
- **`docMeta.js`** — `registerDocument` uploads a file's bytes multipart to `POST /v1/docs` (tags travel with it; an optional project link is a fail-soft follow-up request) and returns the server's authoritative `{docId, dedup, state}`. The single place both the index path and the convert path register a document, so the sequencing can't drift between the two call sites. The old client-side chunk upload (`uploadPdf.js`) is gone — the server derives chunks itself from the verified bytes.
- **`apiErrors.js`** — the one central refusal-to-notice mapper (`describeRefusal`/`noticeFor`): reads the `{error, message, reason?}` body FastAPI wraps refusals in and turns it into toast text, keyed mostly by HTTP status — 409 `content_shared` picks `other_holders`/`in_project` wording, 413/415/422(`empty_file`)/404 get fixed copy, 5xx is the only case that blames the server, and anything else falls back to the body's own `message`.
- **Tool calling is entirely server-side now (C1).** `src/lib/chatTools/` is gone from the browser; the registry lives in `server/chat/tools/` (see [Backend](#backend) below). The `current_time_date` tool is also gone: the current time is written into every prompt instead of costing a tool round.

### Utils

- **`apiFetch.js` / `url.js`** — see [the one rule](#the-one-rule-same-origin-v1). `buildApiUrl(host, port, path)`: blank host → relative path; bare host gets `http://`; port appended only if not already embedded.
- **`wavConcat.js`** — stitches WAVs by reusing the first header and concatenating data payloads; **assumes identical PCM format** (callers guarantee same voice+speed). Audiobook export depends on this.
- **`markdownToSpeech.js`** — strips fences/links/markers; headings get a trailing `:` so TTS pauses.
- **`docHash.js`** — WebCrypto sha256 of file bytes, memoized per name+size. Used to key IndexedDB and the per-document state maps, and sent as `client_doc_id` on upload — but it's only a **hint**: the server computes its own hash from the bytes it receives, and that value is the authoritative `doc_id` if the two ever disagree (a stale or lying client).
- **`attachment.js`** — 10 MB image / 25 MB audio caps; `stripAttachmentData` before persisting sessions (base64 payloads never reach Postgres).
- **`resolvePath.js`** — href classification for workspace links: external / anchor / unsafe (`javascript:` etc. rendered inert) / relative path with `..` normalization.

## Backend

### App wiring

`server/app.py: create_app()` wires in this order — order is load-bearing:

1. **Logging** (rotating file + console, `logging_config.py`) — plus a second rotating file for the **audit trail** (`server.audit` logger, `LOG_AUDIT_FILE`, default `<LOG_DIR>/audit.log`): one line per change to who holds what (entry added/removed, share created/revoked, placement added/removed, content GC'd), IDs only, never file names or search text.
2. **CORS** — `FRONTEND_ORIGIN` unset → no cross-origin caller; pinned → exact origins, credentials **on**; `*` → any origin, credentials **off** (`appconfig.py`).
3. **SessionMiddleware** (starlette signed cookie) — holds *transient OIDC flow state only* (state/nonce/PKCE). This is deliberately separate from the app session, which is a DB row. `SESSION_SECRET` missing → ephemeral per-process secret, which is why `WORKERS>1` without a shared secret silently breaks OIDC (each worker signs with a different key).
4. **Routers**: TTS, chat sessions (`chat_sessions.py`) + chat turns (`chat_turns.py`, the streaming orchestrator endpoint), docs, tools, auth, admin, **inference** (`GET /v1/inference/models` only, listing every configured provider; the list is the environment's allow-lists, then narrowed to the console's **Chat models offered**, and a sized Ollama model carries `context_size: {fixed, auto}` for Settings). The **LLM router** (`server/llm/router.py`, `start_router()`/`stop_router()`) is started/stopped with the app lifecycle and owns one shared httpx client used by every configured provider adapter, not one client per provider.
5. **Startup**: `startup_guard()` (fail fast on auth-bypass or weak secret with a non-loopback bind), `init_db()` (retrying; **failure does not kill the app** — TTS keeps serving, DB-backed routes return 503), embeddings/web-search httpx clients, the document storage dir (`DOC_STORAGE_DIR`, falling back to the pre-A1 `PDF_STORAGE_DIR`, then `./data/pdfs`).

The design theme is **"TTS never dies"**: Postgres down → 503s on chat/doc routes only; SearXNG down → a web search comes back as an error the assistant reads and works around; Keycloak down → login 503s. The only boot-time refusals are the two security guards.

### Auth subsystem

`server/auth/` — all of it is worth reading, but the shape is:

- **`config.py`** — `AUTH_ENABLED` (default **true**), OIDC vars, `SESSION_TTL_HOURS=168` (absolute), `SESSION_IDLE_HOURS=12` (unused this long ends it; 0 = off), `COOKIE_SECURE=true`. Loopback detection resolves the *bind address* through `ipaddress` (never a client Host header — spoofable). `startup_guard()` refuses to boot if auth is off or the secret is short on a non-loopback bind.
- **`oidc.py`** — Authlib client, discovery-based, **PKCE S256**.
- **`sessions.py`** — DB-backed app sessions. Cookie holds a random token; only its **sha256** is stored, so a DB leak yields no usable cookies.
- **`users.py`** — JIT provisioning on login. Three branches: known identity → refresh email; matching **verified** email → link; brand-new → **first-user-admin**: an atomic conditional `UPDATE ... WHERE oidc_sub IS NULL` claims the seed admin row (the row lock serializes concurrent first logins); everyone else lands as `pending` member. An unverified email can never claim the pre-provisioned admin row. **Only the first-user-admin branch force-grants `{admin,reader,chat}`** — the known-identity and email-claim branches mirror exactly the token's realm roles, so a founder pinned via `BOOTSTRAP_ADMIN_EMAIL` with no realm roles is left at zero capabilities (founder-lockout trap — see [IDENTITY_AND_ROLES.md](IDENTITY_AND_ROLES.md)).
- **`tokens.py`** — personal access tokens (`nrp_...`, sha256-stored, shown once). These are how the browser extension and scripts authenticate.
- **`deps.py`** — `get_current_user`: Bearer PAT first, then the `nr_session` cookie, else 401. Non-active status → 403 with the status in the detail (the SPA distinguishes `pending` from `disabled` on this). **Dev bypass**: `AUTH_ENABLED=false` + loopback bind → every request is the seed admin.
- **`authz.py`** — ownership checks raise **404** (not 403) on other people's rows so callers can't enumerate.

**The login round-trip** (`server/routers/auth.py`): `GET /v1/auth/login?next=...` stashes the post-login path in the signed cookie (validated same-site path only — no open redirects) and 302s to the IdP → `GET /v1/auth/callback` exchanges the code (Authlib verifies state + PKCE), provisions the user, creates the session row, and 303s back to `next` with the `nr_session` httponly cookie. The SPA has **no callback route** — it just re-probes `/v1/auth/me` after the reload.

For the full identity map — how Keycloak's `keycloak` schema and the app's `users` table relate (and don't), why `sub` UUID persistence matters, and where roles live — see [IDENTITY_AND_ROLES.md](IDENTITY_AND_ROLES.md).

### Routers

- **`docs.py`** — the RAG pipeline plus the **Library** surface, built on the A1 content/entries model (spec: [superpowers/specs/2026-09-25-document-content-entries-design.md](superpowers/specs/2026-09-25-document-content-entries-design.md)): content (`documents`, keyed by `doc_id` = SHA-256 **computed by the server** from the uploaded bytes, regex-gated `^[0-9a-f]{64}$` because it's interpolated into filesystem paths) belongs to nobody; a `library_entries` row ("I have this") belongs to one user, a `project_documents` row belongs to a project. State machine: `stored → extracting → extracted → indexing → indexed | failed` (`registered` is legacy-only, pre-A1 rows with neither bytes nor chunks). `POST /v1/docs` is multipart — the server hashes the bytes itself, a `client_doc_id` is only a hint — and returns 200 (known bytes: instant entry, no rework) or 202 (new bytes: background extract-then-embed job). Extraction (`services/extract.py`) replicates the reader's own page/section-splitting rules exactly, so a chat citation's page number always matches; indexing embeds in batches of 16 under a per-doc lock; search is pgvector cosine distance. Docling conversion (PDF → per-page markdown) lives here too. Read routes honor **`can_read`** (entry holder or member/owner of a project the content is placed in — a **404**, never a 403, for non-readers), resolved by the single predicate in `server/auth/authz.py` (`readable_docs_where` + `readable_docs_params`); content-changing ops (convert, delete converted markdown, re-index an already-`indexed` doc) are refused **409 `content_shared`** unless the caller is the sole holder or an admin. `GET /v1/docs` lists entries plus placements (`q`/project/tag filters); `PATCH /v1/docs/{id}` sets the caller's own `file_name`/tags only — there's no owner to reassign any more; filing a document into a project is `projects.py`'s `PUT /v1/projects/{id}/docs/{doc_id}` (it can answer `409 name_exists` / `older_version`; the caller retries with `as_version_of` or `keep_both`), and removing a document and every version operation (list, history, upload, restore, delete a version, merge) live in `project_documents.py` under `/v1/projects/{id}/documents` (rules in `services/doc_versions.py`, see [LIBRARY.md](LIBRARY.md) "Versions (V1)"). `PUT`/`DELETE /v1/docs/{id}/shares/{user_id}` replace the old per-doc grants. `GET /v1/docs/{id}/file` serves the stored bytes to anyone `can_read` allows (never cached), which is how the Library's **Open** button and a chat citation open a document the browser doesn't have. **`POST /v1/docs/{id}/chunks` and `POST`/`DELETE /v1/docs/{id}/pdf` are removed** — bytes arrive once, at registration, and chunks are always server-derived, never client-supplied.
- **`projects.py`** — owner-only project CRUD and membership, plus project↔document links: an **upload**-entry holder files a document in; only the project (A1: its owner; A0: Maintainer+) removes it, so the person who filed it has no special standing over the placement. Backs the Library's sharing model (migrations `009`, `010`, `011`).
- **`chat_sessions.py`** — session CRUD as plain relational + JSONB: `GET`/list, `PATCH` (rename), `DELETE`, and `POST /sessions/import` (create-only; copies a legacy IndexedDB-only session's messages onto Postgres the first time you send on it — replaces the old whole-record `PUT` upsert, which is gone). **No pgvector here.** Ownership 404s; messages ordered by timestamp with a role tiebreaker.
- **`chat_turns.py`** — `POST /v1/chat/sessions/{id}/turns`: validates the request (413 over `CHAT_MAX_REQUEST_MB`, 404 not-yours, 429 budget, 409 `turn_in_progress`, 503 `no_providers`/`db_unavailable`; C2.1: `context.project_id` sets, clears (`null`) or keeps (absent) the chat's project, and a project the caller isn't a member of is a 404 that also clears the stored scope; `context.web` is the approved web search), then hands off to the orchestrator and frames its event dicts as SSE (one `data: {...}` line per event, always ending `data: [DONE]`; an unhandled exception still gets a generic terminal `error` frame, never a bare disconnect).
- **`tools.py`** — `POST /v1/tools/web_search`, kept for any external caller; the chat orchestrator's own `web_search` tool calls the same service function directly, not this endpoint. Since C2.1 it returns results only (`{title, url, site, snippet}`); it used to fetch and summarize each page. It answers 403 when the chat's web search mode is `off` (admin setting, then `CHAT_WEB_SEARCH`), resolved as a chat turn resolves it.
- **`admin.py`** — list/patch users; disabling hard-revokes their sessions. Also the inference governance endpoints: `GET /v1/admin/inference/usage` (per-day per-user token rows, `days` clamped 1..90), the per-user `inference_daily_token_budget` field on the PATCH (`exclude_unset` semantics: absent = untouched, explicit null = clear), and the Deployment config view (every provider's name/kind/host/model-count-or-"unreachable", the embeddings `OLLAMA_URL`, allowlist, summarize/embed model — never a key), and `GET`/`PUT /v1/admin/chat-options` (C2.1: the web search mode; `PUT {"web_search": null}` resets to the server setting). Admin console v2 phase 1 adds three routes (all `require_admin`): `GET`/`PUT /v1/admin/settings/{section}` (sections `deployment`, `documents` and, since phase 2a, `models`; the response is always `{settings, info}`: each setting as `{value, source: admin|env|default, env, fallback, fallback_source}` plus the server's read-only rows; `PUT {"changes": {name: value}}`, `null` resets one; a refused value is a 422 `invalid_setting` naming it and saves nothing; an unknown section is a 404 `unknown_section`) and `GET /v1/admin/overview` (the health checks, below). The chat-options route is unchanged. Phase 2a adds `GET /v1/admin/models` (the catalog the Models section chooses from: `providers` with `kind`, `host`, `detected` local|cloud and `reachable`, `models` with `reported_window` and `cloud_name`, and `limits.num_ctx_max`; every chat model the *environment* allows, not narrowed by the console's own selection, and an unreachable provider is listed with no models) and search on `GET /v1/admin/users`: `q` (case-insensitive substring of email, username, display name, first or last name, or first and last together), `status`, `capability`, `limit` (default 50, at most 200) and `offset`, ordered `created_at, id`, with the match count before paging in the `X-Total-Count` header (exposed through CORS in `app.py`). With none of those parameters the route still returns every user, which the older `AdminPanel` relies on.
- **`settings.py`** — `GET /v1/settings/defaults` (the users' defaults) and, since admin console v2, `GET /v1/settings/docling`: what the convert dialog may offer *this* person (`{enabled, may_convert, presets, ocr, picture_description, max_pages}`, from `docling_limits.user_view`). Any signed-in user may read it; it carries no secret and no env name.
- **`inference.py`** — `GET /v1/inference/models` only: every configured provider's models as `{id, provider, kind, name, capabilities}` (`id` is `<provider>:<model>`) plus the caller's budget state. Chat itself no longer has an endpoint here — see `chat_turns.py`.
- **`endpoints.py`** — TTS + `/v1/health` (see [TTS pipeline](#tts-pipeline)).

### The chat orchestrator (`server/chat/`) and provider layer (`server/llm/`) — C1

Chat turns run entirely server-side now; the browser has no chat transport logic beyond reading an SSE stream.

- **`chat/orchestrator.py`** — `run_turn(ctx)`: an async generator of event dicts. One **step** = one model call; text/reasoning stream out as deltas (a step's opening text is held back only while it could still be a tool call the model wrote as JSON text — up to `TEXT_TOOLCALL_PROBE_CHARS`, 2,000 characters — and, if it is one for an offered tool with no native call on the step, it runs as that call and is never shown); a complete tool call runs immediately and its result is appended before the next step. After `CHAT_MAX_TOOL_ROUNDS` rounds (default `3`, or `CHAT_PROJECT_MAX_TOOL_ROUNDS`, default `5`, in a project chat; the last round's results say so, repeated calls aren't run again, and tool results share a per-answer budget, `CHAT_TOOL_RESULT_BUDGET_CHARS`) it forces one last step with tools off, so a turn always ends in an answer. A provider error or the daily budget running out mid-turn ends the turn in a terminal `error` event with the partial reply saved; a disconnect (Stop button, closed tab) is cancellation — the partial reply is saved `aborted` and the session's turn-claim is released, even though the generator is being torn down.
- **`chat/context.py`** — Stage 0, the cheap work before the model runs: prefetch matching passages from the open document (`CHAT_PREFETCH=auto|on|off`, default `auto`: only for a model without document tools; `CHAT_PREFETCH_MIN_SCORE`, `CHAT_PREFETCH_K`; v2.4: with `on` and tools offered, delivered as a `search_documents` tool exchange, else a fenced block in the user message), today's date for the rules from the browser's IANA timezone (falls back to UTC on a garbage value), and history trimming to `context_window − CHAT_REPLY_RESERVE_TOKENS` (old image/audio attachments are replaced by a text marker before any whole turn is dropped). One leading system message (ruling R9 revised in v2.3): the deployment's assistant profile (v2.4), then the rules from `chat/prompt.py`, then a project chat's map of the project (C2.1), then the pins. Prompt order is that system message → history → the new message (→ the prefetch tool exchange) — pins moved out of "right before your message" so providers can reuse the unchanged prefix across turns. The shape fits strict chat templates (vLLM with Gemma or Mistral reject any system message but the first, and two same-role messages in a row): all pins are one leading system message, for a model without tools the prefetched passages lead the new user message's content (then a blank line, then the question), and consecutive same-role history messages are merged, so roles strictly alternate. Only the model input is built this way; the stored user message is what the user typed.
- **`chat/store.py`** — turn claims (`active_turn_id`, one turn per session; a second send gets `409`), a 15-second heartbeat, and stale-claim recovery (a claim older than 60 seconds is a dead worker's; the next thing that touches that session — opening it, or a startup sweep — marks it `aborted` and frees the claim). Also where messages/events are actually written as a turn streams.
- **`chat/tools/`** — `search_documents`, `read_document_pages`, `extract_from_documents`, `document_outline`, `web_search`, `read_web_pages`, `offer_web_search`, one file per tool (`name`, `spec`, `source`, `available(ctx)`, `execute`, `summarize`). This is the only tool registry in the codebase; the old frontend one is gone.
  - v2.4: the strategy the model follows (which source, in what order) is one procedure in `chat/prompt.py`, assembled from the tools offered and pinned by a golden test; a tool's `spec.description` says what it does and how to use it, and never names another tool. `chat/sources.py` works out the pages an answer drew on (the source chips).
  - A key of `execute`'s result that starts with `_` reaches `summarize` but not the model.
  - `ToolContext` is per turn: `shown` holds the chunk ids the model already has.
- **`llm/router.py`** — loads `INFERENCE_PROVIDERS` (unset → one `ollama` provider from `model_router`'s legacy config) and resolves a model id's `<provider>:` prefix to a provider instance, falling back to the first `ollama`-kind provider for a prefix-less (pre-C1) id.
- **`llm/providers/`** — `ollama.py` and `openai_compat.py` adapters share `base.py`: HTTP error mapping, tool-argument JSON parsing (invalid JSON becomes `{}`, reported to the model as a recoverable error), a per-model memory of features a provider has rejected (tools, thinking, a thinking level — remembered only after the retry *without* the feature succeeds), and `safe_error_message` (redacts `sk-…`/`Bearer …`/URL `user:pass@` patterns, then trims to 300 chars) so a provider's raw error text can reach an `error` event without leaking a key.

### Project chat, the reader and web consent (C2.1)

Design: [superpowers/specs/2026-10-18-project-chat-design.md](superpowers/specs/2026-10-18-project-chat-design.md) (where the build ruled differently, the spec carries an "Amended:" note). How the user sees it: [USER_GUIDE.md](USER_GUIDE.md#asking-a-whole-project). Settings: [DEPLOYMENT.md](DEPLOYMENT.md#project-chat-the-reader-and-web-search).

- **Scope (`chat/project_scope.py`).** A chat is about nothing, the open document, or one project (`chat_sessions.scope_project_id`, `ON DELETE SET NULL`). Access is the route's job and is re-checked every turn: `require_project_role(…, admin_ok=False)` in `chat_turns.py`, so a non-member admin is refused too; a 404 there also clears the stored scope. The documents come only from `doc_versions.list_project_documents` (current versions, so an old version is never searched), each given a `ref` (its position, from 1) and a name unique within the scope, and each indexed one goes through `doc_pipeline.ensure_current`. `tools/scope.py`'s `scope_docs(ctx)` is the one place that decides what the document tools read (the project's indexed documents, else the open document as ref 1), so widening the scope changed no tool's own access logic.
- **The map (`chat/project_map.py`).** `build_map` writes `<project_documents>` into the system message, after the rules and before the pins: per document its ref, name, page count, state if not indexed, "open in the reader", and an outline (headings of levels 1-3 with pages) or, with none, its opening line. Everything in it is someone else's text and goes through `display_name` (one inert line), and the data rule names the tag. It is a pure function of the scope and the stored outlines, so its bytes are the same from turn to turn and the provider's prefix cache survives. Over `CHAT_PROJECT_MAP_CHARS` it is shortened by the first step of `STEPS` that fits: level 3 dropped; level 2 kept with the first 8 headings per document; level 1 only with the first 8; names and pages only. (The cap comes before dropping level 2 because a Markdown outline has one level-1 heading, the title, so dropping level 2 first leaves the cap nothing to cut.) A document is never cut, however many there are. When anything was cut the map says so and `document_outline` is offered for the turn; on a turn that offers no tools the note is only "Outlines are shortened." and names no tool.
- **One balanced search (`services/doc_search.search_scope`).** One function for one document or many. It builds a meaning list (an exact scan inside a MATERIALIZED CTE over the scope's chunks: a plan that walks the HNSW index would filter `doc_id` only after keeping `ef_search` candidates library-wide, and lose the scope's passages whenever other documents are closer) and a word list (chunks containing every query word; when none does, chunks with at least half of the query's informative words, most words first, which counts for a tenth of an all-words match in the fusion), then fuses them once by reciprocal-rank fusion (`RRF_K` 60). `_balance` then walks the fused ranking and lets a document give `CHAT_SEARCH_PER_DOC` passages until k are chosen, filling a shortfall from the skipped ones in rank order. Fusion depth is `CHAT_PROJECT_FUSION_DEPTH` for a project and 20 for one document. `exclude` (the chunk ids the model already has) is set aside before balancing, so a follow-up search reaches a document's deeper passages. The per-document cap and fusion depth apply to project scope only; partial word matching applies to both.
- **The reader (`chat/reader.py`).** A sub-agent, not a tool: a separate model call with a fresh context and no tools, given the chat model's goal (`need`) and a batch of labelled passages (`[2, page 6]` for a document, `[web 1]` for a page; labels are built from ref and page only, never from a title), returning `{"found": bool, "facts": [{fact, quote, from}]}`. The app never trusts a fact on the model's word. `verify` checks every quote against the passage its label names, or another passage of the batch (then the label is corrected), or drops the fact: quote and passage are normalised alike (NFKC, case, curly quotes, dash kinds, soft hyphens, a word hyphenated at a line end taken either as kept or as joined, spaces between Han or Kana characters ignored), the fenced form the model actually saw also counts, and a quote needs at least 4 characters (2 with a Han or Kana character) unless it is the whole passage. The fact that survives takes its page from the passage that holds the quote; that is where a citation's exact page comes from. Only verified facts reach the chat model, and `found` is true exactly when one verified, whatever the model said (a `found: false` reply that lists a verifying fact keeps it). A call's `num_ctx` is the turn's, not its own: the orchestrator settles one size per turn (`_turn_reader`, below) and puts it in `ReaderConfig.num_ctx`, so Ollama never sees two sizes for one loaded model and reloads it. `fit_input_chars` then cuts each batch to what that window holds (the brief, the question and goal, the reply cap and `NUM_CTX_MARGIN` taken off, at 3 characters a token), never above `READER_INPUT_CHARS` and never below 500, and `batches` puts at most `MAX_BATCH_PASSAGES` (16) passages in one, which is what lets the label lines be counted. With no `num_ctx` (a cloud or `openai`-kind reader) the batch is `READER_INPUT_CHARS`. `num_predict` comes from `READER_OUTPUT_CHARS`; `read_many` runs batches `READER_MAX_CONCURRENCY` at a time, and `READER_TIMEOUT_S` counts from when a batch gets its slot. A provider error, a timeout or JSON that doesn't parse is a failed batch (`error`), never an exception. The model is the console's Models → Reader, else `READER_MODEL`, else `SUMMARIZE_MODEL`, else `WEB_SEARCH_SUMMARY_MODEL`, else `chat`, the turn's own model (no second model in RAM); `llama3.2:3b` is no longer a default. Logs carry counts and error types, never source text or quotes. The brief is pinned by a golden test. Each batch's call is charged to the turn's user: `read_many` hands a `BatchCall` (model, messages, output so far, the provider's usage if any, finished or not) to `ToolContext.charge`, which the orchestrator wires to `_charge_reader`; that records it with the chat steps' writer (`_record_usage`: the provider's count, else characters / 4), charges a failed or timed-out batch only if it produced something (`_billable`), and never refuses: the next step's budget check does. `Router.complete` fills a `Received` (text, reasoning, usage) as the stream arrives so a cut-off call still shows what it produced.
- **The model settings, resolved per turn (`chat/orchestrator.py`, phase 2a).** Nothing here is cached per process (`WORKERS > 1`): the `models` row is read once per request, and `run_turn` reads it once per turn with `_models_settings()` on a short pool connection of its own, failing open to `model_settings.from_env()` so a Postgres hiccup never stops a chat. In order: (1) the route (`chat_turns.post_turn`) refuses a model outside the console's **Chat models offered** with 422 `model_not_allowed`, after the environment's own check and before the provider listing; (2) the orchestrator resolves the chat model to its provider, asks `sizes_context` whether it needs a size, and replaces the request's `num_ctx` with `num_ctx_for(...)`, so every call of the turn sends that one number; (3) `_window` is the history-trimming window: that `num_ctx` for an `ollama`-kind provider, else the model's reported window, else the declared one (`declared_window`), else none, in which case history is not trimmed (the Overview says "Unknown"); (4) `_turn_reader` settles the reader once and hands it to the tools in `ToolContext.reader_cfg`: the model is the console's Reader, else the environment's chain, else the chat model; a reader the router can't place keeps its name and no size (its calls fail as the reader's own provider error, never the turn); a reader on a model `sizes_context` rejects (Ollama cloud, `openai`-kind) sends no size, even if the person set one for their chat; a reader that is the chat model uses the chat's size; a different self-hosted reader gets `num_ctx_for(..., user_value=None)`, never the person's. `GET /v1/inference/models` reads the same row on its request's connection (fail-open) to narrow the list and fill `context_size`. If the row is unreadable, the environment's `INFERENCE_LOCAL_NUM_CTX`, then 16,384, applies.
- **`extract_from_documents`.** Takes 1-5 documents and a need. Candidate pages are the ones asked for, else all, keeping only pages that have text (a blank page neither takes a place in the cap nor is listed as unread). Over `CHAT_EXTRACT_MAX_PAGES` the pages chosen are those holding the best-ranked chunks for the need (`search_scope` with no per-document cap); if the ranking fails it takes pages in order and says so. A page longer than `READER_INPUT_CHARS` is cut into pieces that overlap by 200 characters, so a quote across a cut is whole in one piece; pages are packed into batches, code fenced as `read_document_pages` does it. The result lists facts per `(ref, page)`, the pages `not_read` and the pages `failed`, and is cut to `CHAT_EXTRACT_OUTPUT_CHARS` by dropping the last facts (`more` counts them). That limit is measured on compact JSON, but `result_text` indents the result by 2 spaces for the model, so what the model gets is typically 15-25% bigger. Verified quotes are added to `ctx.evidence` as `(document, page, quote)`: that feeds the source chips.
- **`web_search`, `read_web_pages`.** `web_search` returns numbered results (`title`, `site`, `url`, `snippet`) from SearXNG and nothing else; numbers continue across the turn in `ctx.web_results`. `read_web_pages(results, need)` accepts only 1-3 of this turn's result numbers (a URL found in a document could otherwise carry document text out), fetches each page under the SSRF guard, picks the passages that best match the need and the search (word overlap, no embeddings), and runs each page as its own reader batch. A page whose reader failed comes back as a fenced excerpt of at most 1,500 characters. Web text never enters `ctx.seen_text` (the guard that keeps document text off the web) or `ctx.evidence` (document pages).
- **Web consent (`services/chat_options.py`, `chat/web_consent.py`, `tools/offer_web_search.py`).** Modes `ask` (default) | `auto` | `off`, resolved per turn (admin row, else `CHAT_WEB_SEARCH`, else `ask`). The rule is enforced by what is offered, not by the prompt: `web_search.available` is true only in `auto`; in `ask` the only web tool is `offer_web_search`, whose call ends the turn with a saved `web_offer` note (`{query, reason}`) that the client shows as `WebOfferCard`. If the model wrote no text in the offer's round, the turn first takes the existing tools-off final step to write its answer (the offer's result carries `web_consent.offer_note`: one of three notes, for a project with a searchable document, the one searchable document, or nothing the model can search (including a project whose documents are all still being indexed), chosen by the same `prompt.document_tools_offered` condition the rules use for "search the document first"), and the card (`data-web-offer`) follows that text; a provider failure at that step still ends the turn with the card, an exhausted daily budget skips the step and sends a `data-notice` with the card, and a Stop during the step saves the text and no card. Approval is a new turn with `context.web = {query}`: the app cleans the query (`clean_query` removes invisible and direction-changing characters, exactly as the card does, so the query sent is the query shown), runs `web_search` itself before the model's first step as a tool exchange with call id `app-web-1`, skips the copied-from-a-document guard (the user wrote or read it), and, in `ask` mode, offers `read_web_pages` and `offer_web_search` for that turn, never `web_search`. (In `auto` mode an approved turn gets that mode's tools as usual, `web_search` included; in `off` mode the approval is ignored.) One yes is one search: a different query needs a new offer. `offer_web_search` is `unmetered`, exempt from the turn's tool-result budget and the repeated-call check, because its result is about 150 characters and must always reach the turn.
- **The strategy (`chat/prompt.py`).** Still one numbered procedure assembled from the tools offered, pinned by three golden turns (`GOLDEN_ALL`, `GOLDEN_PROJECT`, `GOLDEN_APPROVED`). A project chat cites `(Name, page N)`; what the documents lack may be filled from general knowledge if the answer says so and gives it no page, or by an offer. The approved turn's live-information line says the results are above and tells the model to read them or offer another search. With no document tools there is no answer step, so the "name the site of a web fact" sentence goes on the live-information line. `search_documents` says "in the project's documents" when it finds nothing in a project.
- **Citations and sources (`chat/sources.py`, `src/lib/citations.js`).** The model cites `(Name, page N)`; the reply saves a `scope` note (`[{ref, docId, name}]`) and the client links a citation only when its name is in that note (case-insensitive, longest name first), never from the reply text alone. The server and the client count citations by one rule per part: a part is NAME, comma, a page form (`page 3`, `pages 3-5`, `p. 3`, `pp. 4 and 6`), right after `(` or `;` and right before `;` or `)`, so a joined `(A, page 3; B, page 1)` counts as two parts and a page list counts every page. A range counts every page when it spans up to 10 (`RANGE_PAGES`), else only its two ends. A bare `(page N)` counts only when the reply's evidence came from exactly one document. `sources_by_document` gives `[{docId, docName, pages, used}]` for the chips; `web_sources` lists the pages a reader returned facts from, http and https only, with inert titles. If you change one of the two parsers, change the other and its tests: a citation the server counts but the client doesn't link (or the reverse) makes a chip say "used" for a page that nothing links to.

### Services

- **`doc_content.py`** — who holds content (spec §3, §5): the only module that writes `library_entries`/`project_documents` changes and the only one allowed to `DELETE FROM documents` — routes never do that directly. Owns the sole-holder check for content-changing ops (`content_ops_refusal`: an admin, or exactly one entry, theirs, and no project placement — otherwise `other_holders`/`in_project`) and `gc_content_if_orphaned`, called after every path that removes an entry or placement, because a SQL `ON DELETE CASCADE` never runs Python. A startup sweep (`db.py`) catches anything a caller forgot to GC.
- **`doc_storage.py`** — resolves `DOC_STORAGE_DIR` (falls back to the pre-A1 `PDF_STORAGE_DIR`, then `./data/pdfs`), enforces `PDF_UPLOAD_MAX_MB`/`TEXT_UPLOAD_MAX_MB` (413), and type-checks by extension + magic bytes (`%PDF-` for PDF, valid UTF-8 for text/markdown; anything else or a NUL byte in text → 415; 0 bytes → 422). Bytes are written to a temp file and moved into place only after the row insert commits, so a concurrent GC can never delete a file a newer upload just wrote.
- **`extract.py`** — server-side text extraction that **replicates the reader's own page/section-splitting rules** (`src/utils/segmentation.js`) exactly, not approximately: PDF via `pypdfium2` (one chunk per non-empty page), text via sentence-splitting grouped 40-per-page, Markdown via a CommonMark+GFM→mdast-equivalent parse (loose lists and tables are one node, never split on blank lines). Pinned by committed parity fixtures (`server/tests/fixtures/segmentation/`) so a citation's page number always matches what the reader jumps to.
  - C2.1 adds three things to Markdown extraction that are not the reader's. A top-level fenced or indented code block becomes a `code` chunk on the page it already occupies, interleaved with the prose in document order (a block nested in a list or quote stays part of that block's text). A table's cells are separated by spaces in the chunk text so their words are searchable, while pages are still counted from the reader's glued text. And extraction returns an outline (headings of levels 1-3, or a PDF's bookmarks, each with its page) and an opening line, stored by `services/doc_outlines.py` in `doc_outlines` (migration 021, one row per content). The parity fixtures compare the non-code projection, so the reader's layout stays pinned. `CHUNKER_VERSION` is `split1:{max}:{overlap}:code1:cells1`; bumping the last parts makes each document rebuild on first use (the rebuild embeds only text with no stored vector).
  - After extraction, `split_chunks` cuts chunks longer than `CHUNK_MAX_CHARS` into overlapping parts. Each part keeps its page; later parts are typed `…+cont` so a page can be joined back exactly (v2.3). This step is separate from the reader-matching extraction, whose fixtures are unchanged.
- **`embeddings.py`** — Ollama `nomic-embed-text`, **dimension 768 hard-coded** in the SQL column too; swapping to a model of another dimension requires dropping the column; a same-dimension model swap rebuilds each document on first use (v2.3 embedding profile). Semaphore(4); failed texts return `None` rather than aborting the batch. URL + model come from `model_router` config, not env reads.
  - `embed_query` and `embed_documents` add the model's prefixes (`search_query: `, `search_document: ` for nomic).
  - `doc_search.search_scope(…)` (C2.1) is the one search over one or many documents (see [Project chat](#project-chat-the-reader-and-web-consent-c21) below); the earlier description of `search_chunks` still holds for a single document.
  - `doc_search.search_chunks(…, text=)` fuses the meaning ranking with an exact-word ranking (`doc_chunks.text_search`, a `'simple'` tsvector with a GIN index, migration 015) by reciprocal-rank fusion. Each row carries its cosine `score` and `by_words`.
  - `current_profile()` is `model|prefixes|chunker`. `documents.embedding_profile` records it.
  - `doc_pipeline.ensure_current(doc)` starts one background `run_rebuild` for a document made under another profile. The old chunks answer until one transaction swaps the new set in; a document embedded by another model reads as `reindexing` until then.
- **`model_router.py`** — the legacy single-Ollama config: `INFERENCE_MODELS` allowlist (unset = all, dev), no summary model of its own (`SUMMARIZE_MODEL` and `WEB_SEARCH_SUMMARY_MODEL` are older names in the reader's chain, `READER_MODEL` first, see below; `GET /v1/admin/inference/config` reports the reader's resolution, console included, under the old `summarize_model` key), `EMBEDDING_MODEL`, `INFERENCE_TIMEOUT_S`, `INFERENCE_DAILY_TOKEN_BUDGET` (0/unset = unlimited). Pure env parsing; `get_config()` re-reads the environment on every call. **C1:** chat model *choice* moved to `llm/router.py` (`INFERENCE_PROVIDERS`); this module still supplies the no-config default `ollama` provider and the non-chat model settings above.
- **`inference_budget.py`** — per-user daily token accounting. Day is computed in **Python, in the deployment's timezone** (`deployment_settings.deployment_zone`: the console's value, else `TZ`, else UTC; `reset_at` = the next *local* midnight, built from the local date so it stays right on a daylight-saving night) — never a SQL default; rows already written keep their days when the zone changes; PK `(user_id, day)` upserts. Per-user column NULL = deployment default, 0 = unlimited. Callers **fail open**: budget errors never block chat.
- **`web_search.py`** — `web_search()` is a SearXNG query and nothing else: `{title, url, site, snippet}` per result, no page fetch and no model call. `fetch_page_text()` is what `read_web_pages` uses to fetch one page (**SSRF guard**: DNS must resolve to public addresses only, and redirects are followed manually with the check re-applied at every hop, max 4), extract it with trafilatura, and `page_passages()` cuts it at lines into passages of about 1,000 characters and keeps the ones that share most words with the goal and the search, in page order, up to `READER_INPUT_CHARS`. Each fetch is capped three ways: the final hop is streamed and cut off at `WEB_SEARCH_MAX_RESPONSE_BYTES` rather than buffered whole, the whole walk (redirects included) runs under one `WEB_SEARCH_FETCH_TOTAL_S` deadline, and a non-text `Content-Type` is skipped before any body is read. The old per-page summary (`summarize_one`, `WEB_SEARCH_MAX_PAGE_CHARS`) is gone.
- **`chat_options.py`** — the deployment's chat options (C2.1): today the web search mode, from the admin console's `app_settings` row `chat_options`, else `CHAT_WEB_SEARCH`, else `ask`. Read once per turn (one primary-key read, no cache). `save_chat_options(None)` deletes the row, so the next two apply again; each change writes an audit line (who, old mode, new mode).
- **`doc_outlines.py`** — the stored outline of a document (headings or PDF bookmarks with pages, plus an opening line), saved in the same transaction as the chunk swap so chunks and outline never come from different extractions.
- **Admin console v2 (phase 1), five services; phase 2a adds a sixth, `model_settings`.** Spec: [superpowers/specs/2026-10-25-admin-console-v2-design.md](superpowers/specs/2026-10-25-admin-console-v2-design.md). **No migration:** a section is one `app_settings` row (`deployment`, `documents`, `models`; `chat_options` and the assistant profile were there already).
  - **`console_settings.py`** — the one row pattern. A `Section` is a key plus `Setting`s (`env`, `default`, `parse`, optional `narrow`). Each setting resolves console row, then env var, then default, first match winning; an env value that doesn't parse is warned about once and ignored. `narrow` keeps the console's value inside its fallback, so the console can only narrow what the environment allows (allow-lists are intersected, switches ANDed, a limit is the lower). The row is read on every request (one primary-key read, **no cache**), so a save applies at once on every worker. `save` merges with jsonb operators, so a concurrent admin's other keys, and keys a newer version wrote, survive; it writes one `audit()` line per changed setting (who, key, before, after), and a `null` removes a key. The values are settings, never secrets. `view` is what the route sends (the fields above).
  - **`deployment_settings.py`** — the `deployment` section, so far `timezone` (env `TZ`, default UTC). `zone_name` checks a name against the zone database (the only process-level cache: `available_timezones()` can't change while the process runs; `tzdata` is in `requirements.txt` for Windows) and keeps paths like `../etc/passwd` out. `deployment_zone(conn)` is what `inference_budget` and the orchestrator's "Today is" fallback call, each failing open to UTC.
  - **`deployment_info.py`** — the Deployment section's read-only rows (`{id, label, value, env, source}`), read from the `env` it is given with the owning module's names and defaults. A secret (`SESSION_SECRET`, `OIDC_CLIENT_SECRET`, `KC_ADMIN_CLIENT_SECRET`) shows only `set` / `not set`; a URL loses its user info, query and fragment, and a malformed one shows a placeholder instead of raising (`url_host` is the shared helper).
  - **`docling_limits.py`** — the `documents` section (`convert_by`, `presets`, `ocr`, `picture_description`, `max_pages`; env `DOCLING_CONVERT_BY` / `_PRESETS` / `_ALLOW_OCR` / `_ALLOW_PICTURE_DESCRIPTION` / `_MAX_PAGES`) and the rules a convert request is held to. `check(limits, options, …)` is the one place the rules live: `POST /v1/docs/{id}/convert` calls it before `start_convert_job` marks anything `converting`, and refuses with 403 `convert_not_allowed` (`option`: `convert_by`, `preset`, `ocr`, `picture_description`, `max_pages`). `convert_by=role` needs the `docling` capability; admins always pass. OCR off refuses Accurate too, because `docling_convert` sets `do_ocr` for Accurate whatever the flag. A page limit counts the requested range, or, with no range, the file's pages: from `documents.page_count`, or by opening the stored file when that is still NULL (just uploaded, indexing running); a file pdfium can't open skips the limit. `user_view` is the dialog's copy of the same rules.
  - **`model_settings.py`** (phase 2a) — the `models` section: `reader` (`"chat"` or a model id; env is the first set of `READER_MODEL`, `SUMMARIZE_MODEL`, `WEB_SEARCH_SUMMARY_MODEL`, which `models_env` puts under `READER_MODEL`), `context_size` (env `INFERENCE_LOCAL_NUM_CTX`), and the maps and list `context_sizes`, `context_windows`, `provider_locality`, `chat_models` (console only; `INFERENCE_<NAME>_CONTEXT_WINDOW` is read by `declared_window` per provider). `load_models_settings(conn)` is one primary-key read with no cache; `from_env` is what applies when the row can't be read. Two predicates answer two questions and must not be mixed up. `sizes_context(provider, model)` asks whether a request must name its own `num_ctx`: any `ollama`-kind provider, except `-cloud`/`:cloud` models and the ollama.com host; it ignores where the host is, because Ollama's 4,096-token default hits a remote GPU box too, and it ignores the admin's Local/Cloud mark, which is cost-only (ruling P15). `is_local` is the cost flag (the Overview's quota hint, usage later, the catalog's **Auto** label): localhost, loopback or private IPs, 100.64.0.0/10, a single-label name, or a name ending `.local`, `.lan`, `.internal`, `.home.arpa`, one trailing dot ignored, unless the admin's per-provider override or an Ollama cloud model name says otherwise. `num_ctx_for(ms, model, local=sizes_context(...), user_value, limits)` is the one place a request's size is decided: for a sized model the first set of `context_sizes[model]`, the deployment size (`context_size`, console then env), the person's own value, `DEFAULT_LOCAL_NUM_CTX` (16,384), always clamped by `INFERENCE_NUM_CTX_MAX`; for any other model the person's value clamped, or none. `offered(models, ms)` narrows the environment's chat-model list to the console's selection (empty selection = all; a selection whose models are all gone = none). Model ids compare without a trailing `:latest` (`same_model`, `lookup`).
  - **`console_overview.py`** — `GET /v1/admin/overview`: six checks (providers, reader, context windows, embeddings, Docling, web search), each `{id, state: ok|warn|error|off, title, summary, section, items}`. The database reads (chat options, the stale-embedding count, the assistant profile) all happen first, one after another, and no check is handed the connection: a check cancelled by its timeout mid-query would leave the psycopg connection unusable. The network checks then run concurrently, each under `CHECK_TIMEOUT_S` (5 s), so one silent provider costs one line. The embedding check makes its own single POST to `/api/embeddings` (the URL, model and body `embed_one` uses, no `dimensions`) rather than calling `embed_one`, which waits on the shared indexing semaphore; an HTTP error status reads "answered HTTP 404", only a connect or timeout error reads "Can't reach". `window_for` gives the context check each model's window: `/api/ps` `context_length` for a loaded Ollama model, else for a model `sizes_context` accepts the size a request to it sends (so Ollama's `/api/show` maximum is never reported as the window), else an Ollama cloud model's maximum, the provider's reported window, the admin's or `INFERENCE_<NAME>_CONTEXT_WINDOW`'s declared one, else "Unknown". The Reader check reads the Models settings (a hung provider costs the quota hint, never the reader line), and the check warns when the console's chat-model selection offers nothing. The models settings are one of the database reads done first; if they can't be read the checks use `model_settings.from_env`. Whether a project turn fits compares the window with an estimate (4 characters a token) of the system rules, the tool specs, the assistant profile, a full project map and tool-result budget, plus the reply's reserve.
- **`docling_convert.py`** — PDF→Markdown, disabled by default (`DOCLING_ENABLED=false`), lazy imports so the server boots without docling installed. Presets fast/standard/accurate; heavy sync work in `asyncio.to_thread`.

### Projects, roles and activity (A0)

- `project_members.role` (reader < contributor < maintainer < owner) is the
  only source of project access; `projects.created_by` is history. Every
  project route starts with `authz.require_project_role` (404 non-member,
  403 `insufficient_role`); responses carry `can` from `authz.can_for`, and
  the UI renders from it.
- Membership writes take `SELECT … FROM projects … FOR UPDATE` first and read
  the caller's role after it, so concurrent changes on one project serialize
  and the last-Owner rule can't be raced (`services/project_members.py`).
- `project_events` gets one row per change in the same transaction
  (`services/project_events.py`); `audit.log` stays the operators' trail.
- The people directory (`services/people.py`) owns the person-label rule and
  the `USER_DIRECTORY_*` modes.

### TTS pipeline

`server/model.py` loads Kokoro (~325 MB) **at import time** — missing model files are a hard `exit(1)`. Execution provider priority: CUDA → OpenVINO GPU → NPU → CPU, with fallback at session creation — but only the providers of the *installed* ONNX Runtime build exist. `requirements.txt` and the container install the CPU build, so out of the box this is CPU; an accelerated build is a manual swap (README, Hardware Acceleration).

The critical invariant: **Kokoro is not thread-safe**, so all inference runs in an executor under a **global `asyncio.Lock`** (`server/endpoints.py`). Concurrent requests queue rather than corrupt the voice files. This is why the frontend's bounded prefetch matters, why `batch_synthesize` holds the lock for one whole batch instead of per-sentence, and why the request-size caps (`TTS_MAX_*` in `schemas.py`) exist — one oversized request under a global lock stalls TTS for everyone.

### Database & migrations

Single `psycopg AsyncConnectionPool`, pgvector codec registered per connection. Pool connections run with `jit=off` (`POOL_CONN_KWARGS`) because the planner overestimates the `GET /v1/docs` row count and Postgres JIT would otherwise compile the query, adding up to ~340 ms per request at scale for a workload that never benefits from it. Migrations are plain `.sql` files in `server/sql/`, applied in numeric order, one transaction each, versioned in `schema_migrations` — no external tooling. The interesting ones: `001` (documents, chunks with `vector(768)` + HNSW cosine index, chat tables), `005` (users + ownership columns + the seed admin row), `006` (sessions + PATs, hashes only), `007` (`inference_usage` PK (user_id, day) — **day computed in Python/UTC, no SQL default** — plus `users.inference_daily_token_budget`), `008` (`users.capabilities` + backfill — the `reader`/`chat`/`admin` realm-role mirror), `009` (`projects`, `project_members`, `doc_grants`, `documents.project_id`/`tags` — the Library access model), `010` (`project_documents` join table — many-to-many projects↔documents, backfilled from and replacing `documents.project_id`), `011` (content vs. entries — drops `doc_grants`/`documents.user_id`/`documents.tags`, renames `pdf_path`→`bytes_path`, adds `documents.extracted_by` and the new `library_entries` table; owners backfill to `upload` entries, grants to `shared` entries; see [LIBRARY.md](LIBRARY.md#upgrade-notes-migration-011)). `020` (`user_avatars`: one profile picture per user, PNG, JPEG or WebP up to 256 KB; the browser shrinks it to 256 px first). `021` (C2.1: `chat_sessions.scope_project_id` with `ON DELETE SET NULL`, and `doc_outlines`). `022` (`documents.conversion_progress`: Docling's latest progress report while a conversion runs, for the Convert button's page count; NULL otherwise). Restart crash-recovery (`doc_content.recover_states`) rewinds stale `extracting`→`stored` and `indexing`→`extracted` rows and clears a stale `conversion_state='converting'`, then a sweep GCs any content nothing references any more.

## End-to-end flows

**Index a document (reader RAG).** Open a PDF → `usePdfEngine` saves bytes to IndexedDB (for the local library/resume list) → `registerDocument` (`src/lib/docMeta.js`) uploads the raw bytes multipart to `POST /v1/docs`, with the client's own sha256 riding along only as a `client_doc_id` hint → the **server** computes the authoritative hash. Known bytes → `200 {dedup: true, state}`, already indexed, nothing more to do. New bytes → `202 {state: "extracting"}`, a background job extracts (server-side, page-parity with the reader) then embeds → poll `GET /v1/docs/{id}` every 2s through `extracting → extracted → indexing → indexed`. Only once `indexed` does `search_documents` advertise itself to the chat model.

**Convert with docling.** `registerDocument` first (the server already has the bytes — there is no separate PDF-upload step) → `POST /v1/docs/{id}/convert` with options → backend chains convert → seed chunks from `doc_pages` → embed → poll until `converted` + `indexed` → the reader switches to the markdown view (`MarkdownReader`), fetched via `GET /v1/docs/{id}/markdown` with `<!-- page N -->` markers. Convert, delete-converted-markdown, and re-index (on an already-`indexed` doc) are refused **409 `content_shared`** unless the caller is the document's sole holder (one entry, theirs, no project placement) or an admin — converting changes what every other holder reads.

**One chat turn (C1, entirely server-side).** The browser POSTs `/v1/chat/sessions/{id}/turns` (`postTurn` in `chatStream.js`) with the message, attachments and settings; a session that doesn't exist yet is created on this first turn, titled from the prompt. The server (`server/routers/chat_turns.py` → `server/chat/orchestrator.py`) checks the daily budget, claims the session (409 if another turn is already streaming), then runs Stage 0 (document prefetch, time-in-prompt, history trim — `chat/context.py`) and enters the step loop: one model call, text/reasoning stream out as SSE deltas → if the model asked for tools, they run **in the order given** (not in parallel), each result streamed as `tool-output-available`/`tool-output-error` and appended to history → next step, up to `CHAT_MAX_TOOL_ROUNDS` rounds, then one final tools-off step so the turn always ends in an answer. The reply is written to Postgres as it streams (flushed at most every 2 seconds), so a reload mid-reply **in another tab or device** can show "Still generating…" via `applyEvent`/re-fetch; a same-tab reload or close instead drops the connection, so the turn ends in `aborted` and the reply is saved "Stopped". Meanwhile `chatTtsMode='streaming'` flushes complete sentences to the TTS queue as they form. Any feature a provider rejected (tools, a thinking level) arrives as a `data-notice` event → toast. The turn ends in exactly one of: `finish` (usage + stats), a terminal `error` (provider failure, budget exhausted mid-turn), or cancellation (`aborted`, partial reply kept) — every one of these also charges the daily budget for whatever was generated, using the provider's own token count if it reported one, else a chars/4 estimate.

**A page of read-aloud.** `textItems` (sentences) → synthesis for current + next 2, in-flight deduped → `onended` recursion commits position and revokes the played blob URL → end of page bumps `currentPage` (which clears the cache); end of document stops → 3 consecutive failures abort with a toast.

## Local development

`./startup.sh` (see `CONTRIBUTING.md` for the full quick-start):

- `init` — venv, deps, Kokoro model download, frontend build.
- `up` — Postgres + SearXNG + backend with **`AUTH_ENABLED=false`** (loopback bypass: you are the seed admin, no cookie needed).
- `up-with-dev-auth` — adds Keycloak, creates `.env` on first run (rig values + generated `SESSION_SECRET`, `COOKIE_SECURE=false`), waits for the realm import, runs with auth on. Login at :5173 with `admin-user` / `password`.
- `down` — backend + containers down. `up` is foreground; Ctrl-C traps and tears everything down.

The SPA is `npm run dev` on :5173. The Vite proxy makes it same-origin with backend and Ollama; Keycloak at :18080 is deliberately a different origin (the backend, not the browser, talks to it). Backend env vars are read from the environment or `.env` (sourced by `startup.sh` — there is no `python-dotenv`). See `deploy/README.md` for production auth wiring.

## Invariants & traps

- **Blank `apiHost` = same-origin is the only cookie-auth-compatible setup.** Never default it to `localhost`; the migration in `App.jsx` exists precisely because that was once the default and every login-then-fetch silently died to CORS.
- **`isLocalhost` is misnamed** — it really means "use Kokoro TTS" (`true`) vs "browser Web Speech" (`false`). Blank host + `backendAvailable` is what matters at runtime.
- **Kokoro is serialized by a global lock** — any new server-side synthesis path must respect it, and any new client-side path should bound its prefetch (the +2 rule).
- **`WORKERS>1`** means N copies of the 325 MB model *and* — without a shared `SESSION_SECRET` — N different OIDC flow-cookie signing keys.
- **`embedding vector(768)` is hard-coded** — swapping embedding models is a migration, not a config change.
- **Unset inference settings must be omitted, not `null`** (`inference.js`) — `null` clobbers Modelfile tuning.
- **The auth gate blocks rendering, not effects** — App's fetches fire behind the login screen. Don't be surprised by network noise while unauthenticated.
- **Audio attachments ride in Ollama's `images` field** — the message struct has no audio slot; audio-capable models interpret those bytes as audio.
- **Vite watch ignores `.venv`/`data`/`logs`** (`vite.config.js`) — without this, chokidar exhausts `fs.inotify.max_user_watches` on this repo and the dev server dies with ENOSPC.
- **Ownership misses return 404, not 403** (`authz.py`) — leaking existence is an enumeration bug.
- **A document's own hash is not its `doc_id`, the server's is** (`doc_content.py`, `docs.py` `register_document`) — the browser's sha256 (`docHash.js`) only ever travels as `client_doc_id`, an advisory hint logged at WARNING on mismatch. Never key a lookup off the client's computed hash without also handling "the server disagreed."
- **Your own project placement still blocks convert/re-index/delete-markdown** (`content_ops_refusal`) — filing a document into any project you can see (owner or member) counts as another reader of the content, even though you put it there yourself. "Am I the only holder" always checks placements too, not just other people's entries.
- **A cascade never garbage-collects** — every code path that `DELETE`s a `library_entries` or `project_documents` row must call `gc_content_if_orphaned` itself afterward; an SQL `ON DELETE CASCADE` (project delete, user delete) skips it silently unless the caller collected the affected `doc_id`s first. The startup sweep is the safety net, not a substitute for wiring this into a new path.
- **A quote the reader returns is checked, never trusted** (`chat/reader.py` `verify`). A fact whose quote isn't in the passage it names is dropped, and the fact's page comes from the passage that holds the quote. Anything new that turns reader output into evidence must go through `verify`, or a citation could name a page the text isn't on.
- **"Web search asks first" is enforced by which tools exist.** In `ask` mode `web_search` is simply not offered (`available()` is true only in `auto`), and an approved turn runs the user's query in the app. Don't add a route for the model to search that skips `chat/web_consent.py`; a prompt sentence is not a guard.
- **The server counts citations exactly as the client links them** (`chat/sources.py` and `src/lib/citations.js`: names, joined citations, page lists, ranges). They are separate implementations of one grammar; change them together.
- Every `server/sql/NNN_*.sql` must end with
  `INSERT INTO schema_migrations(version) VALUES (NNN) ON CONFLICT DO NOTHING;`
  — the runner doesn't record versions, and a non-idempotent migration that
  re-runs stops startup. `test_every_migration_records_its_version` checks it.
- **Stale docstrings**: `webSearch.js`/`currentTimeDate.js` claim to be unregistered stubs, but both are in the registry — trust the registry line. `VoiceRecorder` is intentionally dead until Whisper lands.
